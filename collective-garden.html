The Collective Garden — Real-Time Multiplayer App

A real-time multiplayer browser experience where users plant, water, and harvest virtual plants in a shared world that evolves through collective action. Built on a Flask + MongoDB Atlas + Socket.IO backend with a p5.js canvas frontend — the garden reflects the presence and care of its community: thriving when active, dimming when quiet.

The Challenge

The problem that needed solving.

Designing a real-time shared environment meant solving synchronization, persistence, and system reliability at once. Every interaction needed to feel immediate while still being consistent across all users. The challenge was not just building features, but ensuring that the system behaved as a single, unified world rather than disconnected client experiences.

🔄

Every user action (planting, watering, harvesting) needed to sync instantly for all connected clients simultaneously.

💾

Persistent plant state — growth stages, health decay, and a hard plant cap — had to be managed reliably in a cloud database.

🐛

Socket.IO events firing inconsistently and updates not broadcasting correctly were the hardest debugging challenges.

📐

Scoping the project correctly: initial vision included weather systems, inventories, and player roles — all had to be cut to deliver a stable core.

02
Process & Solution

How it came together.

01

Architecture

Designed a Flask + Socket.IO server for bidirectional real-time communication, replacing an earlier polling approach that caused lag.

02

Database

Connected Flask to MongoDB Atlas to persist each plant's coordinates, growth stage, last-watered time, and health score.

03

Game Logic

Implemented server-side rules: plant cap enforcement, decay algorithms, and instant DB removal on harvest — all broadcast to every client.

04

Frontend

Built the visual layer in p5.js: each plant renders based on growth stage data streamed from the backend, with subtle animations.

05

Social Layer

Added a global sunlight condition (more users = brighter world) and a live Socket.IO chat system with username selection.

Technical Deep Dive

How the system actually works.

01

Event Flow

User actions trigger Socket.IO events → server validates → updates MongoDB → broadcasts new state → all clients re-render instantly.

02

Plant Lifecycle

Each plant stores timestamps and health values. A decay algorithm runs based on last watered time, gradually lowering health until the plant dies or is removed.

03

State Synchronization

The server enforces all rules (plant cap, growth, deletion) to prevent client-side desync, ensuring every user sees the same world state.

04

Rendering

p5.js listens to incoming state updates and redraws the entire garden each frame based on plant data, creating a smooth visual experience.

Lessons Learned

What this project taught me.

01

Event ordering is architecture

Debugging inconsistent socket events forced a precise understanding of emission order, target scope, and state synchronization.

02

Scope early, or scope late under pressure

The original vision was huge. Narrowing to the core loop made the project both stable and more meaningful — a lesson for every product.

03

Real-time systems require thinking differently

Every action has two lives: what it does locally and what it broadcasts globally. Keeping those in sync is the central challenge of multiplayer.
