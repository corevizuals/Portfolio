The Challenge

The problem that needed solving.

MTELUS needed users to log in and access their accounts faster, while also making Salesforce data actionable for the company. The existing platform had no clear UX structure, making it hard for users to find tickets, history, or personalized recommendations. The challenge: design an intuitive experience that accelerates user engagement and leverages Salesforce data effectively.

🔍

Users couldn't locate essential event info, receipts, or personalized dashboards in the existing environment.

⚙️

Salesforce's data model required a UX structure that exposed complex data without overwhelming the user.

🗺️

No existing UX foundation — the entire hierarchy, navigation, and flow logic had to be built from zero.

⚖️

The layout needed to balance simplicity for casual users with deep functionality for power users managing multiple tickets.

02
Process & Solution

How it came together.

01

Journey Mapping

Mapped all user journeys: viewing booked events, accessing recommendations, managing tickets, and retrieving invoices.

02

Low-Fi Wireframes

Designed low-fidelity wireframes establishing layout, hierarchy, and task prioritization across all screens.

03

Iteration

Iterated across 5 wireframe versions with input from the MTELUS and Evenko teams, simplifying complex flows at each round.

04

Alignment

Established a visual structure that satisfied both Salesforce platform constraints and MTELUS brand standards.

05

Dev Handoff

Delivered fully annotated wireframes with interaction notes, edge cases, and error states for the development team.

Lessons Learned

What this project taught me.

01

Progressive disclosure solves complexity

Dashboard-heavy interfaces need to show users only what's relevant at each step — surfacing everything at once creates paralysis.

02

Platform constraints are design inputs

Salesforce's data model wasn't a limitation to fight — understanding it deeply shaped better, more realistic UX decisions.

03

Wireframes are alignment tools

The real value wasn't the screens themselves — it was the conversations each iteration triggered between UX, dev, and the client.
